# 1. 实现目标

在已经完成问题1的基础上，实现问题2：

- 电价使用 `data/附件1.xlsx` 的单日 144 点电价曲线，每天重复；
- 实际负载和实际光伏使用 `data/附件2.xlsx`；
- 需要为 2025-02-01 至 2025-12-31 每一天，在当天 0:00 制定计划购电策略；
- 制定计划时严禁使用当天及未来真实负载、光伏；
- 使用此前 31 天作为滚动历史场景；
- 建立两阶段随机线性规划；
- 紧急购电价格为对应时段电价的 5 倍；
- 保留问题1的储能约束；
- 生成 `target/附件5/result2.xlsx`；
- 输出论文中表1、表2、表3所需的指定日期结果。

# 10. 第二阶段场景变量

每个场景 `s`、每个时间步 `t`：

```text

surplus[s, t]
```

\[

其中：

- `emergency`：该场景下计划不足时的紧急购电；
- `surplus`：计划供电超过净负荷时无法利用的余量。

# 12. 随机 LP 数学模型

场景数：

```python
S = 31
```

时间点：

```python
T = 144
```

## 12.1 目标函数

\[
\min
\sum_t q_tG_t
+
5\sum_s\pi_s\sum_t q_tE_{s,t}
+
\varepsilon\sum_t(C_t+D_t)
\]

其中：

```python
pi[s] = 1 / 31
```

---

## 12.2 场景电量平衡

对所有：

```text
s = 0..30
t = 0..143
```

建立：

\[
G_t+D_t-C_t+E_{s,t}-W_{s,t}
=
N_{s,t}
\]

`N[s,t]` 为历史场景的净负荷电量。

---

## 12.3 SOC 动态

`t == 0`：

\[
SOC_0
-
0.9C_0
+
\frac{D_0}{0.9}
=
6000
\]

`t > 0`：

\[
SOC_t
-
SOC_{t-1}
-
0.9C_t
+
\frac{D_t}{0.9}
=
0
\]

---

## 12.4 终端 SOC

\[
SOC_{143}=6000
\]

---

## 12.5 Bounds

```text
grid[t]       >= 0

0 <= charge[t]    <= 833.3333333333
0 <= discharge[t] <= 833.3333333333

1200 <= soc[t] <= 10800

emergency[s,t] >= 0
surplus[s,t]   >= 0
```

外网计划购电和紧急购电没有题目给定的功率上限，因此不人为增加上限。

# 16. 当天实际执行评价

求出当天计划后，再读取目标日期当天真实净负荷进行事后评价。

注意：

```text
读取当天实际值只允许发生在计划求解完成以后。
```

定义：

```python
scheduled_net_supply = (
    grid_kwh
    + discharge_kwh
    - charge_kwh
)
```

实际紧急购电：

```python
real_emergency_kwh = np.maximum(
    actual_net_load_kwh
    - scheduled_net_supply,
    0.0,
)
```

实际富余：

```python
real_surplus_kwh = np.maximum(
    scheduled_net_supply
    - actual_net_load_kwh,
    0.0,
)
```

无需为实际评价再次运行 LP。

# 17. 当天费用

计划购电费用：

```python
planned_cost = np.dot(
    price,
    grid_kwh,
)
```

紧急购电费用：

```python
emergency_cost = np.dot(
    5.0 * price,
    real_emergency_kwh,
)
```

总费用：

```python
total_cost = (
    planned_cost
    + emergency_cost
)
```

全天计划购电量：

```python
planned_grid_total = grid_kwh.sum()
```

全天紧急购电量：

```python
emergency_total = real_emergency_kwh.sum()
```

全天实际外网总购电量：

```python
total_grid_purchase = (
    planned_grid_total
    + emergency_total
)
```

程序内部必须同时保存这三个电量指标，不要混淆。

# 19. “计划购电量”工作表

模板数据区域：

```text
A1:EQ335
```

共 334 个正式日期。

列结构：

```text
A      日期
B:EO   144个计划购电时间段
EP     全天购电量
EQ     全天购电费
```

B:EO 必须填写：

```python
grid_kwh[t]
```

即当天 0:00 制定的计划购电量。

不要填写紧急购电量到 B:EO。

## 19.1 时间映射

附件2 B:EO 与结果模板 B:EO 严格按列位置一一对应。

不要自行重新生成或排序时间标签。

```text
附件2 B列 -> result2 B列
...
附件2 EO列 -> result2 EO列
```

这样可以避免日界 `0:00+1` 造成的偏移问题。

## 19.2 EP / EQ 输出约定

本文档统一规定：

```text
EP = 全天实际外网总购电量
   = 计划购电量 + 紧急购电量
```

即：

\[
EP
=
\sum_t(G_t+E_t^{real})
\]

```text
EQ = 全天实际总购电费
   = 计划购电费 + 紧急购电费
```

即：

\[
EQ
=
\sum_tq_tG_t
+
\sum_t5q_tE_t^{real}
\]

同时程序内部必须另存：

```text
planned_grid_total
emergency_total
planned_cost
emergency_cost
```

方便论文分析。

## 30.3 实际结算恒等式

对目标日期真实数据：

```python
scheduled = grid + discharge - charge

actual_emergency = np.maximum(
    actual_net_load - scheduled,
    0,
)

    0,

scheduled + actual_emergency - actual_surplus

只有在本地运行明显过慢时再做。

### 1. 稀疏矩阵

这是必须项。

### 2. 预计算固定矩阵结构

```

每天只更新：

```text

```

### 3. 减少重复对象创建

复用索引与 sparse pattern。

### 4. 并行

第一版不推荐并行。

因为每天场景窗口依赖上一日真实数据，但数据本身已经全部存在；理论上计划计算可以并行，但并行会增加调试复杂度和内存占用。

先保证串行正确。
