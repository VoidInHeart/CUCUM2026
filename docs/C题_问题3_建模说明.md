# C题问题3建模说明

> 本文档用于组内讨论第三问的建模方案。  
> 问题1已经建立确定性储能经济调度模型，问题2已经建立基于历史场景的随机购电模型。问题3在此基础上进一步加入 **日内光伏预测更新与购电计划调整机制**。

---

# 1. 问题3的核心变化

问题2中，每天只在 0:00 制定一次全天购电计划，之后即使预测出现偏差，也只能通过价格为正常电价 5 倍的紧急购电补足。

问题3新增了附件3。每天可以在：

\[
0:00,\quad 6:00,\quad 12:00,\quad 18:00
\]

获得一次新的未来 24 小时光伏发电功率预测。

因此，微网不再需要把 0:00 制定的计划一直执行到当天结束，而可以在 6:00、12:00、18:00 根据新预测重新优化尚未发生的时间段。

问题3的本质因此是：

\[
\boxed{
\text{随机优化}
+
\text{滚动时域优化（Rolling Horizon / MPC）}
}
\]

每天的决策过程变为：

```text
0:00   制定全天计划
  ↓
执行 0:00-6:00
  ↓
6:00   获取新光伏预测并调整剩余计划
  ↓
执行 6:00-12:00
  ↓
12:00  再次更新
  ↓
执行 12:00-18:00
  ↓
18:00  再次更新
  ↓
执行 18:00-24:00
```

---

# 2. 为什么不能简单“每天重新算四次”

第三问并不是四个彼此独立的优化问题。

原因在于三个状态必须跨滚动时刻连续传递：

1. 已经发生的购电不能修改；
2. 已经发生的储能充放电不能修改；
3. 6:00、12:00、18:00 时的 SOC 必须等于此前真实执行策略形成的 SOC。

因此，在 6:00 重新求解时：

\[
0:00\sim6:00
\]

已经成为历史，只能优化：

\[
6:00\sim24:00
\]

12:00 时只能优化：

\[
12:00\sim24:00
\]

18:00 时只能优化：

\[
18:00\sim24:00
\]

这就是典型的滚动时域控制思想。

# 4. 附件3提供的信息

附件3每天有四行预测：

```text
0:00
6:00
12:00
18:00
```

每一行包括：

\[
\text{预报1小时},\ldots,\text{预报24小时}
\]

即某个预测发布时刻 \(\tau\) 下：

\[
\hat P_{\tau,1},
\hat P_{\tau,2},
\ldots,
\hat P_{\tau,24}
\]

分别代表未来第 1～24 小时整点的光伏发电功率预测。

对于当天滚动优化，只使用当前日期剩余部分：

- 0:00 预测使用未来 24 h；
- 6:00 预测使用未来 18 h；
- 12:00 预测使用未来 12 h；
- 18:00 预测使用未来 6 h。

预测中跨到第二天的部分暂不用于本题当天优化。

# 5. 从整点预测转换为10分钟预测

优化模型是 10 分钟粒度，而附件3只有每小时一个预测值，因此需要插值。

本文采用**线性插值**。

设发布时刻为 \(\tau\)，已知：

\[
\hat P_{\tau,1},
\hat P_{\tau,2},\ldots
\]

同时，发布时刻之前已经发生的最新实际光伏状态可以使用，记为：

\[
P_{\tau}^{obs}
\]

形成：

\[
(\tau,P_{\tau}^{obs}),
(\tau+1h,\hat P_{\tau,1}),
(\tau+2h,\hat P_{\tau,2}),\ldots
\]

再线性插值得到每 10 分钟预测：

\[
\hat P^{10min}_{d,\tau,t}
\]

最后转换为电量：

\[
\widehat{PV}_{d,\tau,t}
=
\hat P^{10min}_{d,\tau,t}\Delta t
\]

需要强调：

> 发布时刻以前的实际数据属于已经发生的信息，可以使用；发布时刻以后的实际光伏绝不能用于制定该次调整计划。

---

# 6. 为什么问题3仍然需要考虑预测误差

附件3提供的是预测值，不是真实值。

如果直接把预测值当作完全准确值，则得到的是确定性滚动优化，会低估紧急购电风险。

因此本文继续沿用问题2的随机优化思想，并利用附件3构造**光伏预测误差场景**：

\[
\boxed{
\text{滚动历史场景}
+
\text{光伏预测误差}
+
\text{滚动优化}
}
\]

---

# 7. 历史场景窗口

继续沿用问题2已经通过验证的：

\[
31\text{ 天滚动窗口}
\]

对于目标日期 \(d\)，只允许使用：

\[
d-31,\ldots,d-1
\]

的数据。

任何用于制定目标日期策略的数据都必须满足：

\[
\text{history date}<d
\]

禁止使用目标日期未来真实负载或真实光伏。

---

# 8. 光伏预测误差场景

对于历史日期 \(s\)、预测发布时刻 \(\tau\)，先按照与目标日期完全相同的方法，将附件3小时预测插值为 10 分钟预测：

\[
\hat P^{pv}_{s,\tau,t}
\]

历史日期的实际光伏功率为：

\[
P^{pv,real}_{s,t}
\]

于是预测误差为：

\[
e^{pv}_{s,\tau,t}
=
P^{pv,real}_{s,t}
-
\hat P^{pv}_{s,\tau,t}
\]

对于目标日期 \(d\)，当前最新光伏预测为：

\[
\hat P^{pv}_{d,\tau,t}
\]

则历史场景 \(s\) 下的目标日光伏可能值构造为：

\[
P^{pv,(s)}_{d,\tau,t}
=
\max
\left(
0,
\hat P^{pv}_{d,\tau,t}
+
e^{pv}_{s,\tau,t}
\right)
\]

其含义是：

> 以今天最新预测为中心，叠加过去 31 天曾经实际出现过的预测误差。

相比直接使用历史光伏曲线，这种方式真正利用了附件3的最新预测信息。

---

# 9. 负载不确定性

题目没有提供专门的负载预测。

因此对于历史场景 \(s\)，继续采用过去 31 天同一时间位置的真实负载：

\[
P^{load,(s)}_{d,t}
=
P^{load,real}_{s,t}
\]

将历史负载与同一天的光伏预测误差场景配对，可以一定程度保留两者之间的联合特征。

于是目标日期、更新时刻 \(\tau\)、场景 \(s\) 下净负荷为：

\[
N^{(s)}_{d,\tau,t}
=
\left[
P^{load,real}_{s,t}
-
P^{pv,(s)}_{d,\tau,t}
\right]\Delta t
\]

其中：

\[
t\ge\tau
\]

31 个场景基础版本等概率：

\[
\pi_s=\frac1{31}
\]

---

# 10. 0:00的初始购电计划

0:00 时：

- 获得附件3中 0:00 发布的光伏预测；
- 使用此前 31 天的负载与光伏预测误差构造场景；
- 求解全天 144 个时间段。

变量为：

\[
G_t^0,\quad
C_t^0,\quad
D_t^0,\quad
SOC_t^0
\]

以及场景变量：

\[
E_{s,t}^0,\quad W_{s,t}^0
\]

目标函数与问题2类似：

\[
\min
\sum_tq_tG_t^0
+
5\sum_s\pi_s\sum_tq_tE_{s,t}^0
+
\varepsilon\sum_t(C_t^0+D_t^0)
\]

---

# 11. 6:00、12:00、18:00的调整机制

设调整发生在：

\[
\tau\in\{6:00,12:00,18:00\}
\]

调整前，未来某个时间段已经存在确认购电量：

\[
G_t^{old}
\]

得到新预测后重新确定：

\[
G_t^{new}
\]

定义：

\[
U_t\ge0
\]

为增加购电量，

\[
V_t\ge0
\]

为削减购电量。

满足：

\[
G_t^{new}
=
G_t^{old}
+
U_t
-
V_t
\]

---

# 12. 调整购电费用的解释

题目规定调整购电量高于原计划的部分，按交易时刻电价的 1.5 倍购买，因此：

\[
C^{up}
=
1.5q_tU_t
\]

对于原计划高于调整量的部分，题目称违约电价为交易时刻电价的 50%。

本文将其解释为：

> 原来已经按 \(q_t\) 购买的电量若取消，只能按 \(0.5q_t\) 退回，因此被取消部分损失原价的 50%。

所以削减 \(V_t\) 可以获得：

\[
0.5q_tV_t
\]

退款。

一次调整相对于已有计划的增量结算为：

\[
\boxed{
C^{adj}
=
\sum_t
\left(
1.5q_tU_t
-
0.5q_tV_t
\right)
}
\]

例如原计划 100 kWh，减少到 80 kWh：

- 初始支付 \(100q\)；
- 取消 20 kWh，返还 \(10q\)；
- 最终净支出 \(90q\)。

也就是使用 80 kWh，同时对取消的 20 kWh 承担 50% 违约损失。

若把 50% 理解为在原计划费用之外再额外支付罚金，则削减计划几乎没有经济意义，所以本文不采用该解释。

---

# 13. 多次调整采用逐次结算

一天可能调整三次。

本文采用：

\[
\boxed{\text{每次调整相对于上一版已确认计划结算}}
\]

即：

6:00：

\[
G^{old}=G^{0}
\]

12:00：

\[
G^{old}=G^{6}
\]

18:00：

\[
G^{old}=G^{12}
\]

这符合连续交易过程：每次调整都会形成新的已确认购电量，下一次继续在此基础上修改。

---

# 14. 调整时的滚动优化目标

在 6:00、12:00、18:00，初始购电费和过去已经发生的费用都是沉没成本。

因此当前滚动优化只考虑未来新增成本：

\[
\boxed{
\min
\sum_{t\ge\tau}
\left(
1.5q_tU_t
-
0.5q_tV_t
\right)
+
5\sum_s\pi_s
\sum_{t\ge\tau}
q_tE_{s,t}
+
\varepsilon
\sum_{t\ge\tau}(C_t+D_t)
}
\]

---

# 15. 调整阶段的场景电量平衡

对于剩余时间段：

\[
t\ge\tau
\]

和场景 \(s\)：

\[
G_t^{new}
+
D_t
-
C_t
+
E_{s,t}
-
W_{s,t}
=
N^{(s)}_{d,\tau,t}
\]

其中：

\[
E_{s,t}\ge0,\qquad
W_{s,t}\ge0
\]

分别为紧急购电与富余电量。

# 18. 实际执行策略

每天不是执行某一次优化给出的整天曲线，而是分段执行当前最新策略：

\[
G_t^{exec}
=
\begin{cases}
G_t^0,&0:00\le t<6:00\\
G_t^6,&6:00\le t<12:00\\
G_t^{12},&12:00\le t<18:00\\
G_t^{18},&18:00\le t<24:00
\end{cases}
\]

充放电同理。

# 19. 实际紧急购电

当天真实净负荷：

\[
N_t^{real}
=
(L_t^{real}-PV_t^{real})\Delta t
\]

实际执行策略提供的净电量：

\[
B_t
=
G_t^{exec}
+
D_t^{exec}
-
C_t^{exec}
\]

紧急购电：

\[
\boxed{
E_t^{real}
=
\max(N_t^{real}-B_t,0)
}
\]

富余电量：

\[
W_t^{real}
=
\max(B_t-N_t^{real},0)
\]

紧急购电费用：

\[
C^{emergency}
=
5\sum_tq_tE_t^{real}
\]

C^{plan}

C^{adj}

=

# 21. 为什么问题3属于MPC

每次优化只真正执行下一段：

```text
0:00求解全天 -> 执行0:00-6:00
6:00重新求解 -> 执行6:00-12:00
12:00重新求解 -> 执行12:00-18:00
18:00重新求解 -> 执行18:00-24:00
```

随后使用新预测更新未来决策。

这正是：

\[
\boxed{\text{Model Predictive Control / Rolling Horizon}}
\]

在本题中，内部求解器仍是线性规划，因此可以称为：

\[
\boxed{
\text{基于随机线性规划的滚动时域调度模型}
}
\]

---

# 22. 如何分析是否需要6:00、12:00、18:00预测

不能只凭直觉，应通过消融实验。

主结果采用：

\[
\mathcal P_{all}
=
\{0,6,12,18\}
\]

然后比较：

\[
\mathcal P_0=\{0\}
\]

\[
\mathcal P_6=\{0,6\}
\]

\[
\mathcal P_{12}=\{0,6,12\}
\]

\[
\mathcal P_{18}=\{0,6,12,18\}
\]

比较全年真实总费用：

\[
C_0,C_6,C_{12},C_{18}
\]

新增某次预测的边际价值：

\[
\Delta C_6=C_0-C_6
\]

\[
\Delta C_{12}=C_6-C_{12}
\]

\[
\Delta C_{18}=C_{12}-C_{18}
\]

若：

\[
\Delta C_k>0
\]

则说明该次预测更新带来的成本下降超过其调整交易成本。

---

# 23. 更严格的删除时刻分析

还可以从完整策略：

\[
\{0,6,12,18\}
\]

分别删除某个时刻，得到：

\[
C_{-6},\quad C_{-12},\quad C_{-18}
\]

定义：

\[
V_6=C_{-6}-C_{all}
\]

\[
V_{12}=C_{-12}-C_{all}
\]

\[
V_{18}=C_{-18}-C_{all}
\]

这样可以判断某个更新时刻是否具有独立价值。

# 24. 预测精度也应分析

建议分别统计 0:00、6:00、12:00、18:00 对当天剩余时段光伏预测的：

\[
MAE
=
\frac1n\sum|P^{real}-P^{forecast}|
\]

\[
RMSE
=
\sqrt{
\frac1n
\sum
(P^{real}-P^{forecast})^2
}
\]

不建议用 MAPE 作为核心指标，因为夜间大量真实光伏功率为 0。

如果越靠后的预测 MAE/RMSE 越低，同时其加入后总费用、紧急购电量下降，就可以建立：

\[
\boxed{
\text{预测精度提升}
\rightarrow
\text{滚动调整更有效}
\rightarrow
\text{紧急购电减少}
}
\]

的完整论证链。

# 26. 当前推荐模型

第三问建议采用：

\[
\boxed{
\text{31天滚动历史场景}
+
\text{历史光伏预测误差校正}
+
\text{两阶段随机LP}
+
\text{6小时滚动MPC}
}
\]

整体流程：

```text
0:00最新预测
    ↓
构造31个净负荷场景
    ↓
随机LP制定全天计划
    ↓
执行6小时
    ↓
6:00获取新预测
    ↓
重构场景
    ↓
在当前SOC下重新优化剩余18小时
    ↓
执行6小时
    ↓
12:00重复
    ↓
18:00重复
    ↓
实际偏差由5倍紧急购电补足
    ↓
计划费 + 调整交易费 + 紧急购电费
```

整个模型仍保持在线性规划框架内，不需要遗传算法。
